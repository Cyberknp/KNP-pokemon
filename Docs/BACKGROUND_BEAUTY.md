# 🌄 BACKGROUND BEAUTY — Implementation Plan

**Goal:** Give KNP Pokémon rich, layered scene backgrounds behind (and in front of)
the spawned Pokémon — on par with (and beyond) what [vscode-pets](https://github.com/tonybaloney/vscode-pets)
offers — plus a fast in-panel theme picker so users never need to open Settings.

> **Status:** ✅ Phases 1–5 implemented.
> - Phase 1 — new scenes `volcano` + `snow`, generated by
>   `scripts/generate-backgrounds.mjs` (deterministic, dependency-free; swap
>   in hand-drawn art any time using the same file names).
> - Phase 2 — `vscode-pokemon.select-theme` QuickPick + title-bar button.
> - Phase 3 — `#midground` parallax drift layer (`volcano`/`snow`), paused on
>   hidden panels and reduced motion.
> - Phase 4 — `vscode-pokemon.dayNightCycle` (dark variant 7 PM–6 AM).
> - Phase 5 — `vscode-pokemon.randomTheme` (stable per session).
>
> **Depends on:** Nothing. Each phase is independently shippable.

## 1. Why this plan exists

The README advertises *"extended with new interactions and backgrounds ✨"*, but
the fork currently ships **only the three upstream themes** (`forest`, `castle`,
`beach`) inherited from vscode-pets. No new scene art was ever produced or wired
in, and the default theme is `none`, so most users see a plain empty panel.

This plan closes that gap in five shippable phases, ordered by value-per-effort.

---

## 2. How backgrounds work today (current architecture)

The pipeline is already fully functional end-to-end. Understanding these six
touch points is all you need before adding a new theme:

| # | Touch point | File / location | What it does |
|---|---|---|---|
| 1 | `Theme` enum | `src/common/types.ts:55` | `const enum Theme { none, forest, castle, beach }` |
| 2 | `ALL_THEMES` list | `src/common/types.ts:85` | Used to validate the configured setting |
| 3 | Setting declaration | `package.json` → `contributes.configuration` → `vscode-pokemon.theme` | Enum shown in the Settings UI |
| 4 | Config read + validation | `src/extension/extension.ts:71-77` (`getConfiguredTheme`) + `DEFAULT_THEME` at line 35 | Falls back to `none` for unknown values |
| 5 | HTML injection | `src/extension/extension.ts:1440-1441` | Passes theme name + `themeKind` into the webview bootstrap call |
| 6 | CSS application | `src/panel/main.ts:543-569` | Builds two image URLs and applies them |

### 2.1 The layering trick (the important part)

Each theme is not one image — it is **two stacked transparent-PNG layers**
that sandwich the Pokémon sprites between them, creating a 2.5D scene:

```
┌─────────────────────────────────────┐
│  #foreground  (z-index on top)      │  ← foreground-dark-medium.png
│  ── trees / castle walls / rocks ── │     (transparent PNG, bottom band)
│                                     │
│  Pokémon sprites live HERE          │  ← <img> elements in pokemonContainer,
│  walking on `floor`                 │    lifted up by the floor offset
│                                     │
│  body backgroundImage               │  ← background-dark-medium.png
│  ── sky / hills / horizon ────────  │     (painted behind everything)
└─────────────────────────────────────┘
```

Applied in `src/panel/main.ts`:

```ts
// line 560 — far layer, painted on <body>
document.body.style.backgroundImage =
  `url('${basePokemonUri}/backgrounds/${theme}/background-${_themeKind}-${pokemonSize}.png')`;
// line 562 — near layer, overlaid on #foreground div
foregroundEl!.style.backgroundImage =
  `url('${basePokemonUri}/backgrounds/${theme}/foreground-${_themeKind}-${pokemonSize}.png')`;
// line 564 — raises the walkable "ground" so pets appear behind foreground props
floor = calculateFloor(pokemonSize, theme);
```

Both layers use `background-repeat: repeat-x; background-position: bottom left;`
(defined in `media/pokemon.css:13-36`), so images must tile horizontally.

### 2.2 Asset naming contract (mandatory)

Every theme needs **16 PNGs** — 2 layers × 2 color-kind variants × 4 sizes:

```
media/backgrounds/<theme>/
  background-{dark|light}-{nano|small|medium|large}.png   (8 files)
  foreground-{dark|light}-{nano|small|medium|large}.png   (8 files)
```

A missing file fails **silently** (CSS just doesn't paint) — always verify all
16 exist before registering a theme.

### 2.3 Floor heights

`FLOOR_HEIGHTS` in `src/panel/main.ts:139-159` maps every theme × size to a
pixel offset lifting the walkable ground. A new theme MUST add its own row,
tuned by eye against the artwork's foreground band height.

## 3. How vscode-pets does it (reference model)

vscode-pets uses the identical architecture (this repo is derived from the same
lineage), which validates our approach:

- **Same two-layer system:** `backgrounds/<theme>/background-*` + `foreground-*`
  per color-theme kind and pet scale.
- **Themes as pure data:** adding a theme = drop assets + add enum entry +
  settings enum entry + floor heights. Zero rendering-code changes.
- **Where we will go further than vscode-pets:**
  - Phase 2 — one-click theme switching from the panel title bar (they only
    offer a settings dropdown).
  - Phase 3 — parallax scroll depth (their scenes are static).
  - Phase 4 — automatic day/night variant selection by time of day.
  - Phase 5 — shuffle mode that rotates scenes per session.

## 4. Phase 1 — New theme scenes (assets + registration)

**Outcome:** 3–5 brand-new scenes selectable from Settings.
**Effort:** mostly art; ~30 lines of code total.

### Proposed first batch

| Theme key | Scene concept | Foreground props | Floor vibe |
|---|---|---|---|
| `volcano` | Charizard territory — glowing crater sky, obsidian ground | Basalt columns, lava cracks | Warm dark |
| `snow` | Frosty route — falling snow sky, icy plain | Snowbanks, pine trees | Bright cool |
| `nightcity` | Neon skyline — city lights, starfield | Rooftop edge, lamp posts | Electric |
| `underwater` | Ocean floor — light rays, bubbles | Coral reef, seaweed | Deep blue |
| `cave` | Mt. Moon interior — crystals, darkness | Stalagmites, rock arches | Mysterious |

### Steps (do them in this exact order)

**Step 1 — Produce assets** (see §9 for specs). For each theme, export the 16
PNGs into `media/backgrounds/<theme>/`.

**Step 2 — Register the enum** in `src/common/types.ts:55`:

```ts
export const enum Theme {
  none = 'none',
  forest = 'forest',
  castle = 'castle',
  beach = 'beach',
  volcano = 'volcano',   // ← new
  snow = 'snow',         // ← new
}
```

**Step 3 — Add to `ALL_THEMES`** at `src/common/types.ts:85` (this drives
validation in `getConfiguredTheme`, extension.ts:74).

**Step 4 — Declare in `package.json`**: extend the `enum` array of
`vscode-pokemon.theme` so the Settings UI lists it.

**Step 5 — Add floor heights** in `FLOOR_HEIGHTS` (`src/panel/main.ts:139`),
one row per theme, all four sizes:

```ts
[Theme.volcano]: {
  [PokemonSize.nano]: 23,
  [PokemonSize.small]: 30,
  [PokemonSize.medium]: 40,
  [PokemonSize.large]: 65,
},
```

**Step 6 — Verify nothing else needs touching** (it shouldn't):
- ✅ `getHtml` injection (extension.ts:1440) interpolates any enum value generically.
- ✅ Webview URL builder (main.ts:560) uses the raw string.
- ✅ Live-reload listener (extension.ts:1107) already watches `vscode-pokemon.theme`.
- ✅ CSP allows `img-src ${webview.cspSource}` — local media loads fine.

**Step 7 — Compile & test** (`npm run compile && npm test`, then F5).

## 5. Phase 2 — In-panel theme picker command

**Outcome:** users switch scenes instantly via title-bar button or palette,
without opening Settings.
**Effort:** ~80 lines.

### Steps

**Step 1 — New command** `vscode-pokemon.select-theme`:
- Add to `package.json` → `contributes.commands` with title *"Select background theme"*
  and a landscape icon (e.g. `media/icon/dark-scene.svg`).
- Add an `activationEvents` entry `onCommand:vscode-pokemon.select-theme`.
- Add to `view/title` menus bound to `view == pokemonView` (group `navigation@4`)
  so it appears as a button on the sidebar panel header.

**Step 2 — Implement in `src/extension/extension.ts`** next to the other
command registrations (~line 800+):

```ts
context.subscriptions.push(
  vscode.commands.registerCommand('vscode-pokemon.select-theme', async () => {
    const items = ALL_THEMES.map((t) => ({
      label: t === Theme.none ? '$(circle-slash) None' : `$(${themeIcon(t)}) ${t}`,
      theme: t,
    }));
    const pick = await vscode.window.showQuickPick(items, {
      placeHolder: localize('pickTheme', 'Pick a background scene'),
    });
    if (!pick) return;
    const config = vscode.workspace.getConfiguration('vscode-pokemon');
    await config.update('theme', pick.theme, vscode.ConfigurationTarget.Global);
  }),
);
```

Because the existing `onDidChangeConfiguration` listener (extension.ts:1103-1119)
already calls `panel.updateTheme(...)` + `panel.update()`, **the panel repaints
automatically — no extra wiring needed.**

**Step 3 — Optional nicety:** show a progress toast while the new background
PNG decodes (large `large` PNGs can be ~800 KB).

## 6. Phase 3 — Parallax & animated layers

**Outcome:** scenes feel alive — clouds drift, water shimmer, foreground subtly
shifts as the window resizes.
**Effort:** ~150 lines + optional animated assets.

### Design

Add a third, mid-ground layer between body and foreground:

```html
<div id="midground"></div>   <!-- insert after #pokemonCanvas -->
```

CSS (`media/pokemon.css`):

```css
#midground {
  position: absolute;
  inset: 0;
  z-index: 5;              /* sprites sit at z-index between layers */
  pointer-events: none;
  background-repeat: repeat-x;
  background-position: bottom left;
  animation: drift 90s linear infinite;   /* slow horizontal loop */
}
@keyframes drift {
  from { background-position-x: 0; }
  to   { background-position-x: -1024px; }  /* match tile width */
}
```

### Steps

1. Extend the asset contract with an optional
   `media/backgrounds/<theme>/midground-*.png`. Themes without it skip the
   layer (feature-detect via image load, don't assume).
2. Apply it in `pokemonPanelApp()` (main.ts, alongside lines 560-564) guarded by
   the existing `motionReduced` flag so reduced-motion users get static scenes.
3. Respect `vscode-pokemon.motion`: pause `animation-play-state` when `reduced`.
4. **Performance guardrail:** animate `background-position-x` only (compositor-
   friendly enough at 1 layer), never transform whole DOM trees; keep the drift
   period ≥ 60 s so it costs ~nothing.

## 7. Phase 4 — Day/night auto-switching

**Outcome:** scene picks its dark variant automatically at night, light by day.
**Effort:** ~40 lines.

Today `_themeKind` derives purely from VS Code's color theme kind
(main.ts:547-558). Extend the resolution order to:

1. If setting `vscode-pokemon.dayNightCycle` is `"on"`:
   - hour ≥ 19 or < 6 → force `dark` variant
   - otherwise → `light` variant
2. Else fall back to current behavior (color theme kind).

Steps: declare boolean setting `vscode-pokemon.dayNightCycle` (default `false`)
in package.json; thread it through the options object passed at
extension.ts:1448-1452; apply at the `_themeKind` switch. Re-evaluate hourly via
a `setInterval` inside the webview (cleared alongside the game loop).

## 8. Phase 5 — Random theme rotation

**Outcome:** each session starts with a surprise scene.
**Effort:** ~25 lines.

New setting `vscode-pokemon.randomTheme` (boolean, default `false`). In
`getConfiguredTheme()` (extension.ts:71), when enabled, pick uniformly from
`ALL_THEMES.filter(t => t !== Theme.none)` using `Math.floor(Math.random() * n)`
and cache the choice in `context.workspaceState` so reloads within a session
keep the same scene (avoid jarring flicker on webview rebuilds).

## 9. Asset production guide

Hard requirements for every new theme (matching the existing 24-file layout):

| Property | Requirement |
|---|---|
| Format | PNG, RGBA (transparency required for foreground/midground) |
| Tiling | Must repeat seamlessly horizontally (`repeat-x`) |
| Height | Match the size tier: nano ≈ 200 px, small ≈ 300 px, medium ≈ 400 px, large ≈ 600 px (match existing forest PNG dimensions exactly) |
| Width | ≥ 1024 px, tileable seam |
| Foreground | Bottom band of opaque scenery; everything above transparent |
| Palette | Two variants: `light` (day) and `dark` (dusk) — can share art with a hue/brightness shift |
| Style | Pixel-art consistent with sprite GIFs (silkscreen aesthetic) |

**Tooling tips:**
- Compress with the existing pipeline: `npm run optimize-assets` (gifsicle is
  GIF-only; run `pngquant --quality=65-80` or `oxipng -o max` for the PNGs).
- Keep castle-style sizes in check — `castle/background-dark-large.png` is
  already 793 KB; aim under ~400 KB per PNG.
- Verify tiles: open in any editor, duplicate the layer side-by-side, and check
  the seam at x=0/width boundary.

## 10. Testing checklist

Run per phase — compile first (`npm run compile`), then F5 into the Dev Host:

**Phase 1 (new themes)**
- [ ] All 16 files exist for each new theme (no silent blanks):
      `for k in dark light; do for s in nano small medium large; do test -f media/backgrounds/volcano/background-$k-$s.png || echo MISSING; done; done`
- [ ] Setting shows new enum values in Settings UI.
- [ ] Each size tier renders the correct-resolution art (switch
      `pokemonSize` while theme active).
- [ ] Light AND dark VS Code color themes both resolve a variant.
- [ ] Pokémon walk on the intended ground line (floor heights tuned, not
      floating or sunk into foreground props).
- [ ] Unknown/garbage value in settings.json still falls back to `none`.
- [ ] Existing vitest suite still green: `npm test`.

**Phase 2 (picker)**
- [ ] Command appears in palette; picking a theme repaints instantly, no reload.
- [ ] Title-bar button visible on the explorer view; hidden elsewhere.
- [ ] Cancel/Esc leaves theme unchanged.
- [ ] Persisted choice survives Dev Host restart.

**Phase 3 (parallax)**
- [ ] Drift animation runs smoothly (< 2 % CPU delta measured in Dev Tools
      Performance tab).
- [ ] `motion: reduced` freezes drift entirely.
- [ ] Themes without midground assets degrade gracefully (no broken img icon).

**Phase 4 (day/night)**
- [ ] Forcing system clock (or stubbing hour) flips variant at boundaries.
- [ ] `dayNightCycle: false` preserves exact current behavior.

**Phase 5 (random)**
- [ ] Never picks `none`; stable within one session across webview rebuilds.
